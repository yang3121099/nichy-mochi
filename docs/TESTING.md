## 关键验证

- 同名内容的幂等底层提交、并发提交、串行执行、失败后继续下一任务。
- 快照发布完整性、源文件修改后旧版本不变、错误或被修改的快照不执行。
- 新任务在旧任务运行期间获得独立读取回执，同时显示两个内容版本。
- 快速任务也记录回执；离线不误报收到；过期 worker 不误报正在运行。
- 取消、超时、正常停止、排空、重启、故障锁、`UNKNOWN` 不自动重跑。
- worker 的 SIGTERM、SIGKILL、SIGSTOP；脱离会话及忽略终止信号的后代清理；无关进程存活。
- 自选且含空格的队列路径；`start.sh` 首次初始化；已有配置不覆盖；业务 `start.sh` 可正常提交。
- 配置只在启动时读取，运行期间修改不会生效；重启后应用；错误配置暂停心跳而正式任务继续。
- CUDA_VISIBLE_DEVICES 为空时不扩大设备可见性；不可用指标跳过心跳。

## 隔离和范围

自动测试使用每个用例单独的队列、程序目录和日志。大多数 Linux 模拟提交通过系统 Python 独立进程执行，环境只包含基础 PATH、语言及空的 CUDA 可见设备；执行端使用 GPU 虚拟环境。测试任务没有提交到最终常驻服务的正式队列。

本次验证的目录位于同一容器，独立 SSH 会话也连接同一实例。真实跨主机 NFS 的缓存延迟、断网、服务器失效和挂载一致性未在本次验证范围内。多卡选择策略通过规则测试验证；实际 CUDA 测试使用一张 H200。MIG 和非 NVIDIA 设备没有实际验证。

没有模拟宿主机重启、驱动故障或断电；这些情况应按管理员文档确认旧进程和结果后恢复。文件队列需要支持原子重命名、硬链接和目录 fsync 的 POSIX 文件系统。

## 复现

```bash
python3 tests/run.py --report test-report.json
python3 tests/run.py --gpu --report gpu-test-report.json
```

GPU 测试请使用已分配、当前空闲的设备。设置 `GPUQ_TEST_BASE` 可指定测试目录，`GPUQ_KEEP_TESTS=1` 保留证据，`GPUQ_CLIENT_PYTHON` 指定独立提交端 Python。不设置时使用测试目录下的临时文件夹并在结束后清理。
